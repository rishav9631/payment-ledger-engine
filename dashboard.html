🎯 What is this Dashboard & What is it trying to achieve?

This dashboard serves as the real-time mission control and load testing workbench for a distributed, high-throughput payment transfer system. It enforces a Queue-First Load Ingress architecture engineered for zero data loss, strict 1-minute expiration gates, and high-concurrency burst absorption:

1. Synchronous Kafka Acknowledgment (acks=all) The Ingestion API writes immediately to Kafka with acks=all across in-sync replicas before returning HTTP 202 Accepted. If Kafka is unreachable, it returns 503 Service Unavailable so the client safely retries.
2. Zero-Duplicate Idempotency (SETNX) Incoming transfer requests carry a unique Idempotency-Key header. Redis executes an atomic SETNX with 24h TTL. Any retries return the cached transaction response without double-charging accounts.
3. Strict 1-Minute Expiration Pipeline Dual validation gates: Checkpoint A rejects stale client packets (> 60s) at the gateway with HTTP 408. Checkpoint B verifies now ≤ expires_at before database settlement; expired items write to terminal EXPIRED status.
4. Manual Offset Commits & DLQ Poison Guard Consumers disable enable.auto.commit and commit Kafka offsets strictly after the database write succeeds. Unprocessable poison payloads divert to payment-requests-dlq without halting partition throughput.
